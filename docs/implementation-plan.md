# План реализации веб-прототипа «Пока открыт мост»

Версия 0.1 · настольный браузер · один сценарий

Игрок проходит одну карту дважды и сравнивает, как меняется эвакуация при продлении работы моста или сохранении переправы. На третьем ходу игрок выбирает режим водосброса. Оба контрольных плана вывозят 90 из 108 человек, но полностью эвакуируют разные районы.

Правила и числа берём из [геймдизайна прототипа](game-design.md). Для реализации нужны [карта и расписание](game-design.md#карта-и-данные-сценария), [порядок хода](game-design.md#правила-хода-и-итог-партии) и [контрольные партии](game-design.md#два-плана-эвакуации). Изменения баланса после плейтеста сверяем с этими исходными результатами.

## Порядок работы

Каждый этап заканчивается проверяемым результатом. После него фиксируем, что получилось, что ещё требует решения и с чего начинается следующий этап. Игровые правила утверждаем на схеме из простых фигур. Поиск и интеграция ассетов идут после появления обеих играбельных веток.

В объём 0.1 входят карта из пяти узлов, два автобуса и паром, до восьми ходов, одна развилка и повтор партии. Игра запускается по HTTP в браузере. План рассчитан на ПК с мышью и клавиатурой, на русский интерфейс и игру в одном окне.

## Этап 0. Движок и запуск в браузере

Предлагаемый стек для 0.1 — Phaser 4, TypeScript и Vite. Phaser рисует карту и обрабатывает ввод на ней. Обычные HTML-элементы показывают приказы, прогноз и итоги. TypeScript хранит правила отдельно от отрисовки, Vite собирает статические файлы для браузера.

| Вариант | Что понадобится | Когда выбирать |
| --- | --- | --- |
| Phaser 4 | Проверить доступность пакетов, зафиксировать версии, сделать маленькую сцену и собрать её в `dist`. | Подходит для одной 2D-карты, быстрого повтора и проверки из браузера. |
| Unity 6 Web | Проверить Web Build Support в Hub, сделать 2D-сцену, выбрать Web в Build Profiles и выполнить Build and Run. | Подходит, если дальнейшая разработка должна идти в Unity и работа в редакторе важна уже сейчас. |

На компьютере найдены Node.js 24.13.0, npm 11.6.2 и Unity 6000.6.6f1. В каталоге `PlaybackEngines` этой установки Unity обнаружена только поддержка Windows. Для варианта Unity нужно подтвердить состояние Web Build Support в Unity Hub и при необходимости добавить модуль.

### Что сделать

- **Проверить окружение.** Уточнить доступность реестра npm и наличие актуальных Chrome и Edge. Проверить в браузере, что работает WebGL. Зафиксировать точные версии Node и зависимостей в `README` и lock-файле.
- **Собрать пробную сцену.** В отдельной папке проекта создать страницу с двумя условными узлами, линией между ними и кнопкой. Клик по узлу меняет выделение. Изменение размера окна сохраняет совпадение картинки с областью клика.
- **Проверить два запуска.** Открыть dev-версию через `npm run dev`. Затем выполнить `npm run build` и открыть результат через `npm run preview`. Проверить, что пути к файлам работают при загрузке из подпапки, а игровой экран не тянет шрифты или картинки из CDN.

### Критерий завершения

Пробная сцена открывается по HTTP. Узлы реагируют на клик, а в консоли нет ошибок загрузки или запуска. Выбран и записан один стек для следующих этапов.

## Этап 1. Данные сценария и правила хода

Создать вычислительное ядро и проверить его без игрового экрана. Конфигурация сценария хранит числа, геометрию и сроки. Состояние партии хранит то, что меняется от хода к ходу.

| Данные | Что хранится |
| --- | --- |
| Узлы и участки | У, Р, Б, Ш, Н. Для участка задать пару узлов, допустимый транспорт, вместимость участка и последний доступный ход по каждому режиму. У всех участков длительность в один ход. |
| Старт | Больница 36, школа 18, набережная 54. А1 на развязке, А2 в школе, паром у убежища. У каждого 18 мест. |
| Состояние | Номер хода, выбор водосброса, закрытия, позиции, пассажиры с районом отправления, очереди и число вывезенных по районам. |
| Приказы и события | Для каждой машины — ожидание или соседний узел. На ходу 3 — отдельный выбор водосброса. События описывают закрытие, посадку, движение, высадку и конец партии. |

### Что сделать

- **Открыть ход.** До выдачи приказов применить закрытия. Участок открыт, когда номер хода меньше или равен последнему доступному ходу. Закрытие обеих переправ к У завершает партию сразу.
- **Проверить приказы.** Проверить соседство, тип машины, закрытия и общий лимит моста. На третьем ходу потребовать явного выбора водосброса. Отклонённый набор приказов оставляет состояние прежним.
- **Выполнить подтверждённый ход.** Пустая машина при выезде забирает до 18 человек. Общая очередь распределяется в порядке А1, А2, П. Затем транспорт перемещается одновременно. Прибытие в убежище выгружает пассажиров и обновляет счёт. Движение возвращает новый снимок и события в фиксированном порядке.
- **Закрыть партию.** Показать итог при спасении всех, закрытии обоих входов в У или завершении хода 8. Для каждого района ожидающие, пассажиры в пути и вывезенные в сумме дают исходное число жителей.

### Критерий завершения

Проверки воспроизводят [обе контрольные партии](game-design.md#два-плана-эвакуации). Отдельно проходят проверки границ закрытия, двух встречных автобусов на мосту, ожидания без посадки, высадки только в У и полного сброса. Одинаковые приказы на одном снимке дают один результат.

## Этап 2. Игровая карта и первый маршрут

Собрать первую играбельную версию с расписанием закрытого водосброса. На третьем ходу эта версия использует фиксированный режим. Развилка появится на следующем этапе. Уже здесь можно пройти весь сценарий, увидеть итог и начать заново.

### Что сделать

- **Перенести схему.** Нарисовать реку, высокий берег и низину, соединить пять узлов из [схемы сценария](game-design.md#карта-и-данные-сценария). Автобусные участки обозначить сплошной линией, паромную переправу пунктиром. На мосту поставить ограничение «1 автобус за ход». Для клика задать область вокруг узла шире его символа.
- **Показать состояние.** Вывести название района и число ожидающих, позицию и загрузку каждого транспорта, общий счёт и номер хода. Если несколько машин стоят в одном узле, разнести маркеры или выбрать машину из списка. Для закрытого участка показать засечки и подпись.
- **Подключить приказы.** Клик по машине выделяет только соседние доступные узлы для её типа. Клик по узлу добавляет стрелку приказа. «Ждать» снимает приказ. Ту же операцию можно выполнить кнопками в панели машин, например выбрать А1 и пункт назначения.
- **Связать ход и отрисовку.** Кнопка «Выполнить ход» передаёт набор приказов ядру. При конфликте мост выделяется, рядом с обоими приказами появляется объяснение, а подтверждение блокируется. Успешный ход обновляет карту, очереди, позиции и журнал. На следующем ходу список приказов сбрасывается на ожидание.
- **Подключить итог и повтор.** Сумма спасённых считается только по доставленным в убежище. Итог показывает вывезенных, ожидающих и находящихся в транспорте по каждому району. Кнопка «Повторить» возвращает стартовые позиции, очереди и ход 1.

### Контрольный проход

Вручную провести А2 из школы в У на ходу 2, А1 из больницы в У на ходу 3 и выполнить три рейса парома с прибытием на ходах 2, 4 и 6. Сверить, что нижняя дорога закрывается перед ходом 4, мост перед ходом 5 и переправа перед ходом 7. Последнее закрытие сразу показывает итог.

### Критерий завершения

[План А](game-design.md#два-плана-эвакуации) полностью проходится мышью из браузера. В итоге 90 из 108, больница 18, школа 18, набережная 54. Результат и старт новой партии совпадают с проверками ядра.

## Этап 3. Водосброс и обе ветки

Добавить сравнение прогнозов с первого хода и выбор на третьем. В обеих ветках можно отдать одинаковые приказы на первых трёх ходах. Последующие приказы определят, успеет ли игрок отправить последний паром или сделать второй автобусный рейс.

### Что сделать

- **Подключить сравнение.** Показать две строки расписания с абсолютными номерами последних доступных ходов. Подпись над шкалами объясняет, что проехать можно и в указанный ход. На третьем ходу игрок видит, какие сроки изменятся при выборе каждого варианта.
- **Развести просмотр и подтверждение.** До подтверждения игрок может менять вариант водосброса и текущие приказы. Временный выбор меняет прогноз, но не закрывает участки и не перемещает транспорт. Кнопка выполнения требует явного выбора. После подтверждения ход 3 выполняется один раз, а режим сохраняется до итогового экрана.
- **Обновлять карту и журнал из правил.** После выбора показать активный прогноз на всех связанных участках. Срок закрытия нижней дороги остаётся 3 в обеих ветках. Когда дорога перестаёт быть доступной, запись в журнале и новый статус линии появляются до выдачи следующих приказов.

| Проверка | А · оставить закрытым | Б · открыть |
| --- | --- | --- |
| Последний проезд по мосту | Ход 4 | Ход 7 |
| Последний рейс парома | Ход 6 | Ход 4 |
| Приказы после общего хода 3 | Паром Н → У на 4, У → Н на 5, Н → У на 6. | Паром Н → У на 4. А1 У → Р → Б → Р → У на ходах 4–7. |
| Итог | 90 · Б 18, Ш 18, Н 54 | 90 · Б 36, Ш 18, Н 36 |

### Как проверить вручную

После первой партии нажать «Повторить» и повторить [начальные приказы](game-design.md#общие-приказы-на-первых-трёх-ходах). После ходов 1, 2 и 3 счёт равен 0, 36 и 54. На ходу 3 выбрать другой режим. На ходу 4 сверить общий счёт 72 и различие в том, где находится А1.

### Критерий завершения

Обе ветки доступны с одного экрана. Вариант А заканчивается перед выдачей приказов на ход 7, вариант Б перед ходом 8. При смене режима в предпросмотре счёт, позиции машин и очереди остаются на месте.

## Этап 4. Первый заход и обратная связь

Добавить объяснения в момент, когда игрок впервые сталкивается с правилом. Указание маршрута, прогноз и итог должны считываться с карты и панели без обращения к геймдизайн-документу.

### Что сделать

- **Поставить короткую задачу.** На первом экране показать цель, вместимость транспорта и кнопку подтверждения. Подсказка о посадке появляется при выборе машины. Сохранить возможность самостоятельно решить, куда отправить первый автобус и паром.
- **Сделать план читаемым.** В списке приказов показывать машину, откуда она едет и куда прибудет. У участков с ограниченным сроком отображать «Последний ход 4» или актуальное значение. При конфликте мост и оба приказа отмечаются текстом и символом. Ждать можно на любой машине.
- **Показать исполнение.** После подтверждения коротко выделить маршрут каждой машины, затем обновить посадки и высадки. Длительность перехода ориентировочно 200–350 мс. При системной настройке уменьшения движения результат появляется сразу. Во время перехода повторное нажатие кнопки игнорируется.
- **Объяснить последствия.** Журнал пишет конкретное событие, например «Паром доставил 18 с набережной» или «Мост закрыт перед ходом 5». В итогах показать разбивку по районам, сохранив причину перекрытого маршрута и быстрый повтор.
- **Проверить управление.** Кнопки имеют видимый фокус. С клавиатуры доступны выбор машины и назначения, «Ждать», выбор водосброса, выполнение и повтор. Состояния доступны как подписи и формы. Подсказки об ограничениях доступны при фокусе, а не только при наведении.

### Пробный проход без подсказок

Дать одному человеку запуск с пустой партией. Отметить, когда он понял, как задавать приказы и где увидел прогноз. После выбора на третьем ходу попросить назвать оба изменившихся срока. Если он затрудняется, уточнить текст, расположение или последовательность подсказок и повторить короткую проверку.

### Критерий завершения

Первую партию можно пройти без инструкций разработчика. Ход переключается один раз на подтверждение, а выбранный режим и причины закрытий остаются видимыми до итога.

## Этап 5. Поиск и интеграция ассетов

Подбор начинается после того, как обе ветки проходят на условных обозначениях. Для каждого ресурса сначала проверить, делает ли он приказ, транспорт или закрытие более читаемыми. Затем сверить лицензию конкретного файла и проверить его в масштабе карты.

| Что ищем | Кандидат | Как отобрать |
| --- | --- | --- |
| Пиктограммы и элементы интерфейса | Kenney Game Icons и UI Pack, CC0. | Взять только нужные символы, например предупреждение или повтор. Кнопки и подписи можно оформить средствами HTML и CSS. |
| Шрифт интерфейса | Inter, SIL Open Font License. Системный шрифт остаётся резервным. | Проверить кириллицу, «ё», цифры, знаки стрелок и читаемость на малых размерах. При встраивании сохранить текст лицензии. |
| Короткие звуки | Kenney Interface Sounds, CC0. Freesound — резерв, лицензия указана у каждого файла. | При необходимости выбрать короткие сигналы подтверждения и закрытия. Для Freesound сначала смотреть CC0, для CC BY оформить атрибуцию. |

### Порядок отбора

- **Составить короткий список.** По каждой позиции сравнить 2–3 варианта по контрасту, масштабу и стилю. Узнаваемость моста и транспорта проверять рядом с реальными названиями и числами.
- **Записать происхождение.** Завести `ASSET_CREDITS.md`. Для каждого файла записать имя в проекте, исходную страницу, автора, лицензию, требуемую атрибуцию и внесённые изменения. Копию текста лицензии хранить рядом с ресурсом, когда это требуется условиями.
- **Включить файлы в сборку.** Сохранить локальные копии только выбранных ресурсов. Иконки проверить на светлой суше и голубой воде. Звуки, если они нужны, включать после пользовательского действия и дать управление громкостью или отключением.

### Критерий завершения

В браузере карта остаётся читаемой с выбранными ресурсами и без звука. Все внешние файлы открываются локально из сборки и отражены в реестре ассетов.

## Авторские элементы и генерация ассетов

Для 0.1 генерация изображений и звука не требуется. Схема карты и её игровые состояния создаются из данных. Если нужного открытого ассета нет, для первого теста достаточно авторского условного знака с подписью.

| Элемент | Как создаём | Что проверить |
| --- | --- | --- |
| Геометрия карты | Координаты пяти узлов, берег, река и пять участков. Отрисовка из конфигурации сценария. | Линии и области клика соответствуют одной геометрии. Меняется статус участка, а его концы остаются на своих узлах. |
| Состояния и прогноз | Стрелки приказов, засечки закрытия, бейджи срока и шкалы создаём кодом из событий и расписания. | После переключения прогноза и изменения размера окна значения совпадают с правилами. |
| Маркеры транспорта | Простые формы и подписи А1, А2, П. При желании заменить открытыми пиктограммами после этапа 5. | Автобус и паром различимы по форме. Номер автобуса читается, даже когда две машины стоят в одном узле. |
| Иллюстрация брифинга | Условная задача после плейтеста, если игроки не понимают, что происходит с городом. | Отдельная иллюстрация речной низины и высокого берега. Без надписей и игровых маршрутов. |
| Декоративный фон карты | Условная задача после плейтеста, если схеме не хватает атмосферы. | Если понадобится генерация, использовать приглушённую текстуру бумаги без дорог, строений и символов. Проверить контраст на всей карте. |

### Требования при заказе генерации

Для иллюстрации брифинга подготовить одну горизонтальную композицию 16:9. Основные формы — река, низина и сухой высокий берег. Для фоновой текстуры достаточно одного бесшовного изображения без заметных деталей. Хранить исходник отдельно, а в игру включать оптимизированный файл.

У каждого созданного файла записать происхождение и назначение в том же реестре. Декоративный слой должен легко отключаться. Дороги, позиции машин, подписи, счётчики и прогноз по-прежнему рисуются из игровых данных.

### Когда возвращаться к этому списку

После этапа 7 выбрать, нужна ли визуальная итерация. Если игроки понимают контекст наводнения и различают все состояния карты, оставить условную схему для следующего теста механики.

## Этап 6. Проверка браузерной сборки

Проверять собранную версию в настольных Chrome и Edge по локальному HTTP. Пройти оба плана после чистой загрузки и повторить ключевые действия после смены размера окна. Для проверки логики использовать [контрольные партии](game-design.md#два-плана-эвакуации). В отчёте указать версии браузеров и сборки.

| Ситуация | Ожидаемый результат |
| --- | --- |
| Загрузка и консоль | Игра открывается из сборки без ошибок загрузки. После установки зависимостей локальная игра не обращается к внешним ресурсам. |
| Мост и переправа на границе | Мост принимает последний проезд на 4 или 7. Паром принимает последний рейс на 6 или 4. На следующем ходу соответствующий путь закрыт. |
| Ошибочный и двойной ввод | Два приказа на мост блокируют подтверждение. Двойной клик выполняет только один ход. При недопустимом приказе счёт и позиции прежние. |
| Посадка, ожидание и доставка | Ожидание сохраняет очередь. Выезд пустой машины уменьшает очередь. Счёт растёт только при доставке в У. |
| Наблюдение за выбором | Прогноз доступен с начала. На третьем ходу нужен явный выбор. При переборе вариантов до подтверждения меняются только сроки предпросмотра. |
| Две партии и повтор | Оба итога равны 90 с разной разбивкой. После повтора очищены выбор режима, журнал, приказы и позиции транспорта восстановлены. |
| Размер окна и клавиатура | В 1280 × 720 и 1920 × 1080 карта и приказы доступны. При масштабе 125% элементы можно прокрутить до видимой области. Фокус остаётся видимым. |

### Что сделать при ошибке

Записать версию сборки, браузер, ход, режим, набор приказов и фактический результат. Расхождение в подсчёте сначала воспроизвести на уровне правил. Ошибку клика или отображения повторить в собранном браузерном экране.

### Критерий завершения

Обе ветки завершены в Chrome и Edge. Проверки границ и повторного запуска пройдены. Сборка открывается с локального HTTP-сервера, а карта и панель пригодны для ручного прохождения.

## Этап 7. Передача и первый плейтест

Передать сборку и короткую инструкцию для запуска на компьютере. Попросить сначала сыграть самостоятельно. Контрольные приказы держать в отдельном разделе инструкции, чтобы ими можно было воспользоваться при второй партии.

### Что передать

- **Исходники и сборку.** В папке проекта оставить сценарные данные, исходники, lock-файл, инструкцию и реестр ассетов. Для выбранного веб-стека подготовить каталог `dist` со статической сборкой. На итоговом экране указать версию прототипа.
- **Инструкцию для Windows.** Для готового `dist` указать запуск `npm run preview` и адрес, который напечатает сервер. При первом запуске из исходников сначала выполнить `npm ci`, затем `npm run build`. Для разработки указать `npm run dev`. При выборе Unity описать Build and Run и запуск готового каталога Web через локальный HTTP-сервер.
- **Два контрольных маршрута.** Описать, какие приказы вводить на ходах 1–3 и чем отличаются ходы 4–7. Дать ссылку на [раздел с маршрутами](game-design.md#два-плана-эвакуации) или продублировать приказы в `README` под раскрываемым заголовком.

### Как провести тест

Дать задачу «Вывези как можно больше людей». Записать, когда игрок впервые увидел прогноз, что ожидал от открытия водосброса, кого вывез и начал ли повтор сам. После подтверждения хода 3 спросить, что произойдёт с мостом и паромом. После итога спросить, какой конкретный приказ он изменил бы.

| Что наблюдаем | Что делать с результатом |
| --- | --- |
| Игроки путают последний доступный ход с первым закрытым | Уточнить подпись шкал, проверить читаемость и повторить тест на новых участниках. |
| Игроки понимают сроки, но воспринимают оба исхода одинаково | Проверить, различимы ли последствия для районов в итогах и нужен ли более заметный эффект выбора. Менять один параметр за итерацию. |
| Игроки сами пробуют второй вариант | Сравнить, меняют ли они только водосброс или перестраивают ранние рейсы. Использовать наблюдение для следующей карты или правки первой. |

Ориентиры из [раздела о плейтесте](game-design.md#плейтест-на-десяти-игроках) для группы из 10 человек — 7 объясняют оба изменения сроков и 6 добровольно начинают повтор. Это критерии для следующей итерации. Сборка готова к передаче, когда другой человек запускает её по инструкции и может пройти обе ветки.
